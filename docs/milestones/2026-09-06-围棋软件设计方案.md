# 网页版单机 AI 围棋 — 设计方案

> **里程碑**:项目初始化 · 首版设计方案
> **日期**:2026-09-06
> **说明**:本文为历史存档,记录围棋网站"初始化阶段"(浏览器单机版)的设计方案。
> 后续的架构改造不在本文范围内;当前实现说明见 [AGENTS.md](../AGENTS.md)。

---

## 1. 技术选型(已查证)

- **前端**:原生 TypeScript + Vite,Canvas 渲染棋盘,AI 在 Web Worker 中运行
- **AI 引擎**:KataGo 权重 + TensorFlow.js(WebGPU 优先,WASM 回退)+ 自研 MCTS
  - 查证依据:开源项目 [web-katrain](https://github.com/Sir-Teo/web-katrain) 已用此路线在浏览器内跑通 KataGo 分析(解析 KataGo 权重 v8-v16 格式,上限 128MB)
  - 不采用"C++ 引擎整体编译 WASM":无官方开箱即用产物,自编译工作量大
- **模型**:默认 b18c384nbt(~32MB,浏览器友好),设置中可切换 b6c96(~60MB);权重从 jsdelivr CDN 下载(GitHub release 镜像),IndexedDB 缓存,支持本地导入 .bin.gz
- **棋谱格式**:SGF(标准格式,通用)

```
    ├── engine/

    │   ├── features.ts      # KataGo 输入特征编码(19x19 多平面)

    ├── ui/
    │   ├── board-renderer.ts # Canvas:盘面/棋子/手数/候选点标记/变化线
    │   ├── controls.ts      # 打谱导航(首/前/后/末/自动播放/速度)

    │   └── styles.css
    └── store/
        ├── game.ts          # 对局状态机(手顺、贴目、终局结果)
        ├── review.ts        # 回放状态(当前步、分析结果缓存)
        └── library.ts       # IndexedDB 棋谱库(列表/增删/导入导出)
```

## 3. 子系统设计

### 3.1 规则引擎(core/)
- 棋盘用 Int8Array[361],连通域求气实现提子;Zobrist 哈希检测打劫与重复
- 终局:双方连续 pass 后,数子法结算(中国规则贴 3.75 子;设置可切日本规则数目)
- 职责:UI 落子校验、回放合法性、终局结算;AI 搜索不依赖它(网络自带规则特征)

### 3.2 SGF(core/sgf.ts)
- 解析:GM[1]/SZ[19]/B/W 坐标转换、分支(变化图)、RE/KM/PB/PW、注解(忽略保留)
- 序列化:对局结束或随时保存 → 下载 .sgf 文件 + 存 IndexedDB 棋谱库
- 导入:文件选择器打开 .sgf;棋谱库列表管理(重命名/删除/导出)

### 3.3 AI 引擎(engine/)
- **模型加载**:首次启动从 CDN 下载 → IndexedDB 缓存(后续秒开);解析 KataGo 权重为 TF.js 张量(参考 web-katrain 的 v8-v16 格式解析思路,自研实现);显示下载进度
- **推理**:输入特征按 KataGo 规范编码(19x19 多平面:黑白子、气、劫点、贴目、规则等),输出 policy/value/ownership
- **MCTS(TS 实现)**:PUCT 选择、虚拟损失、节点扩展、批量推理(WebGPU 下 batch 效率高)、回传;支持 maxVisits/时间限制/访问量上限
- **对弈决策**:MCTS 收敛后取访问量最多的合法点(含 pass);难度档位:简单 50 / 中等 200 / 较强 800 / 最强 2000 visits(或限时)
- **Worker 协议**:主线程与 worker 间 postMessage 传输命令、局面、分析流;分析流节流(每秒 ~5 帧)避免 UI 卡顿

### 3.4 人机对弈(store/game.ts)
- 新对局:选黑白、难度、规则;玩家落子 → 本地校验 → 记录手顺 → AI genmove
- 悔棋(撤销双方各一步)、认输、虚着(pass);AI 思考中棋盘显示当前最佳着点预览
- 终局数子结算 → 结果写入 SGF 的 RE;对局全程可随时保存棋谱

### 3.5 打谱与分析(需求 3、4)(store/review.ts)
- 打开棋谱 → 从头回放:导航按钮 + 键盘 ←/→、自动播放(0.5/1/2/3 秒)、跳首末、显示当前步/总手数;分支棋谱可选分支
- **暂停分析**:回放停在任意步 → 点击"分析" → 当前局面发给 worker,MCTS 持续运行
- **候选展示**:棋盘上 A/B/C/D/E 标记 top 候选点(按胜率着色深浅),侧栏列表显示坐标、胜率、目差、模拟量,支持"仅显示最优变化"开关
- **15 步变化线**:点击候选点 → 棋盘显示该候选的后续变化(PV),深度截断为 15 手(可配置 5-30);变化步序在侧栏列出,可逐步播放/回退;支持对变化中的局面再次发起分析(递归查看)
- 分析控制:开始/暂停/停止、每秒更新频率;分析结果按局面哈希缓存,回放往返时秒显

### 3.6 UI 布局(ui/)
- 中央自适应 Canvas 棋盘(坐标标注、星位、最后一手、手数可开关)
- 顶部:模式切换(对弈/打谱)、新对局、打开棋谱、保存、设置
- 右侧可折叠侧栏:对弈信息(黑白/贴目/难度/AI 胜率实时)/ 打谱导航 / 分析面板
- 中文界面;顶部模型加载进度条(下载/解析/就绪三态)

## 5. 提交规范(小步演进)

- **原则**:每个 commit 保持可运行状态;一个 commit 只做一件事;提交历史即演进故事(脚手架 → 棋盘 → 规则 → 回放 → AI → 分析)
- **格式**:Conventional Commits,如 `feat: 落子与提子规则`、`test: 规则引擎单元测试`
- **流程**:每小步完成立即 commit,不攒批;里程碑结束不 squash,保留演进细节;main 单线推进
- **纪律**:提交信息中文简短描述;涉及多文件的同一功能点合并为一条 commit,不同功能点分开提交

## 6. 测试计划

- **规则引擎单测**:vitest 覆盖提子、打劫、自杀、终局数子的典型与边界局面(角/边/大龙)
- **SGF 单测**:解析/序列化往返一致,分支与特殊属性
- **MCTS 单测**:固定种子与 mock 网络下树结构正确、访问分布合理
- **手工验收**:每里程碑后真机跑通关键流程;M3 后验证 AI 与 KataGo 参考对弈胜率分布(如 AI 黑先行对参考引擎胜率 > 40%)

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 浏览器无 WebGPU | TF.js 自动回退 WASM 后端(慢但可用),启动时检测并提示 |
| GitHub/权重下载慢或失败 | jsdelivr CDN 镜像 + IndexedDB 缓存 + 支持本地导入权重文件 |
| 自研 MCTS 终局处理偏差 | 网络自带 pass 倾向特征,MCTS 访问上限下自然收敛;最终结算由本地规则引擎负责,不受搜索影响 |
| TF.js 解析 KataGo 权重格式复杂 | 仅支持主流 b18/b6 权重(v8-v16 格式,与 web-katrain 已验证范围一致),模型列表白名单化 |

## 8. 假设

- 目标平台为现代桌面浏览器(Chrome/Edge/Safari 最新版);"本地打开"通过 `scripts/start.mjs` 一键本地服务器实现(file:// 直开受 Worker/WASM 限制,不作为目标)
- 默认中国规则(数子、贴 3.75 子);KataGo 权重按 7.5 贴目训练,分析胜率口径与其一致
- 不做棋谱云端同步、不做 PWA 离线安装(权重缓存已覆盖离线分析);后续可作为扩展
